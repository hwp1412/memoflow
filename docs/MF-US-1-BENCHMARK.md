# MF-US-1 性能基准（A14）

- 任务：`P2-US1-SIM-01`
- 基准脚本：`scripts/bench-mf-us-1.mjs`（可重复执行）
- 被测函数：`selectDailyQueue`（**仅此函数**，不含脚本初始化、数据构造或 Mercy）
- 基准时间：2026-11-25（模拟环境时间，由脚本记录）

## 1. 环境（必须披露）

| 项 | 值 |
|---|---|
| 机器 | Apple M4（笔记本），10 核 |
| 平台 | darwin / arm64 |
| Node.js | v24.21.0 |
| 进程参数 | 默认（无额外 `--max-old-space-size`） |
| 输入 seed | 20260105 |

> 该机器**不是**服务器级参考桌面，结果不能直接与其他硬件比较；在其他平台需重新执行基准。本文档中的 PASS 仅对本机成立。

## 2. 方法

- 输入：40% Source / 60% Extract；Priority 1–100；Ideal Due 分布 −30…+30 天；成本混合（1/7 为 10 分钟，其余 5 分钟）；约 6% 为 `done`；无 `not_before`（另 1/23 带已过期延期）；预算 30 分钟。
- 规模：100 / 1,000 / 10,000。
- 计时：先记录**冷启动**单次，再连续 25 轮**预热**，报告 median / P95 / max / min / mean。
- 确定性：两次运行的选中 ID 集合 SHA-256 前 16 位一致。
- 输入不可变：冻结前 JSON 与运行后 JSON 逐字节比较。
- Mercy 预览与批次应用单独测量，**不并入** A14 队列阈值。

## 3. 结果

| 规模 | 冷启动 | 中位数 | P95 | 最大 | 选入/候选 | 输入未变 | 确定 |
|---:|---:|---:|---:|---:|---:|---|---|
| 100 | 1.76ms | 0.46ms | 0.66ms | 0.67ms | 6 / 48 | ✅ | ✅ |
| 1,000 | 5.05ms | 4.49ms | 5.18ms | 6.70ms | 5 / 479 | ✅ | ✅ |
| 10,000 | 53.28ms | **53.15ms** | 65.88ms | 124.52ms | 6 / 4,782 | ✅ | ✅ |

**A14 判定（本机）**：10,000 Topic 纯队列计算中位数 53.15ms < 500ms → **PASS**。
（重复执行的 10k 中位数在 52.97–53.15ms 之间，P95 59.6–65.9ms，属于正常抖动。）

Mercy（单独测量，不参与 A14 判定）：

## 4. 结论与限制

- 10k 队列计算在本机余量约 9×，说明当前实现（候选分析 + 五级排序 + 单趟预算）没有明显性能瓶颈。
- 尚未做 profiler 级别的热点归因；若在其他硬件上超出 500ms，应先复测并定位瓶颈，**不得通过修改调度公式或降低候选规模来“优化”指标**。
- 基准脚本本身不计入被测时间；数据构造在计时区间之外。
- 该基准只覆盖纯队列计算；Mercy、事件应用、模拟日循环的耗时另行报告。

## 5. 复现

```bash
node scripts/bench-mf-us-1.mjs
```

脚本输出人类可读摘要 + 完整 JSON（含环境、seed、每轮统计、确定性哈希、A14 判定）。
