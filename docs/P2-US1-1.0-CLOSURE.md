## 2. E2E 合成闭环（通过）

`Source 初始化 → Extract 多级初始化 → ADVANCED → POSTPONE → Mercy apply → 关闭重载账本 → 重复事件 duplicate → Mercy undo → COMPLETE → REACTIVATE`

证据：`test/mf-us-1-closure-e2e.test.js`

- 每次 Unified 事件写前 Intent、写后账本持久化；
- 重载后 E1 重复不增加 `review_count`；
- Mercy 使用 PR-09 批次协议，apply/undo 恢复 `mf_not_before`，不计评阅、不改 Interval；
- COMPLETE/REACTIVATE 保持 Interval/A-Factor/Review Count；
- 账本 flush 失败 → `uncertain`，不宣称成功；
- Unified 失败/未授权不会回退 Legacy（`legacyCalls=0`）。

## 4. 模式切换与 UI 模型

`buildHostModeView` 展示：迁移、恢复、旧写入退场、备份、CAS、用户确认、生产授权七项检查；真实 runtime 永远 `writeEnabled=false`；只有合成授权 + 全部条件才 `writeEnabled=true`。不允许 onload/设置恢复自动启用。

## 5. 账本生命周期

- 版本化 snapshot 加载并校验；损坏 → `healthy=false` + 阻塞 Topic；
- Writer 先写 Intent，再写 Topic，再回读校验，最后标记 applied；
- runtime 在每次事件后持久化；保存失败 → `uncertain`；
- 启动 `recover()` 对 prepared/uncertain 执行 reconcile；无法确认 → `requires-manual-recovery` 并阻塞；
- `saveData()` resolve 不等于断电耐久，文档与测试均不宣称。

## 6. resetCurrent 裁决

Legacy 行为不等于任何 MF-US-1 事件；禁止映射为 MANUAL_SCHEDULE。Unified 下 `E_RESET_CURRENT_UNDECIDED`。若需支持，应新增显式“重置排期”管理事件并修订规范；本轮未新增。
